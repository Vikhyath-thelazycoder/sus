## T-2.1 Curated papers

Metadata (DOI, licence, source URL, authors, journal, year) in `data/papers/metadata.json`. PDFs are re-downloadable from `source_url` and are not committed.

## T-2.2 / T-2.3 / T-2.4 Parsing, sections, chunking

Shared code (browser + Node): `src/shared/pdf/{read,layout,structure}.ts`, `src/shared/chunker.ts`. Parsed output of all 20 papers was written to `data/parsed/*.md` (local, not committed) and read by eye. Problems found while reading, and the fix for each:

| Problem seen | Fix |
|---|---|
| Two-column text interleaved (Frontiers: narrow sidebar + wide body; Nature) | Gutter found as the centre of the widest x-range crossed by the fewest lines, not the page midpoint |
| Wrapped headings cut ("Modifications strategies for promoting…") | Join following same-size short lines into the heading |
| Wrapped sentences / list items / citation fragments taken as headings | Lowercase-continuation rule (body-sized lines), `et al.` / `, 2016` rule |
| Author names and table header rows as headings | Page-1 front matter accepts only standard headings; ≥ 2 standalone numbers ⇒ not a heading |
| Papers cut short by a table column titled "References" | Bibliography starts only if ≥ 2 of the next 6 lines look like reference entries |
| Figure captions running into sentences | Paragraph break on a font-size change |
| Double-spaced manuscript: one paragraph per line | Paragraph gap relative to the section's median line spacing |
| Manuscript line numbers interleaved with text | Numeric-only lines within 15% of the left/right edge removed |

**Result:** 881 chunks, average ≈ 330 tokens (target ≈ 350), all ≤ the 4,000-character server limit. Known remaining limitations: a few section labels come from figure or table text (e.g. "Insects Crustaceans", "DPL10 DPL10 CSL80"); no text is lost, only the label in the chunk header is imperfect. Superscripts can be dropped (e.g. "g/m²" → "g/m").

## T-2.5 Table quality check

Tables come out as **flat runs of cells**: every value is kept, but rows and columns are lost (e.g. mycelium paper Table 1: "Fibre group Source Type Processing Particle size (mm) … Hemp Loose (hurds) 5–25 HL M1 …"). Keyword search can still find values; the LLM may misread which value belongs to which row. **Recommendation for the MVP (T-9.5):** test Docling or Workers AI `toMarkdown` on the table-heavy papers; for the demo, keep pdf.js.

## T-2.6 Ingest endpoints

`POST /api/admin/papers` (paper + sections) and `POST /api/admin/papers/:id/chunks` (≤ 32 chunks): admin token, strict zod schemas, server-side deterministic IDs from owner + DOI, upserts, invisible-character stripping, old vectors deleted on re-ingest. Tests: `test/admin-papers.test.ts` (6), `test/node/server.test.ts` end-to-end through the REST adapters.

**Live idempotency:** re-ingesting the same paper twice left exactly 1 paper / 23 chunks / 4 sections.

**CPU on the Workers free plan** (measured with `wrangler tail`): batches of 20 chunks used 27 ms; batches of 6 used 10–30 ms; paper creation 8–23 ms; all over the 10 ms limit at times. Per the owner's rule (PROJECT_PLAN, demo hosting), **the demo moved to Render** (D-012): same Hono app on Node, data on Cloudflare via REST.
