# P4 evidence: Answer generation

Date: 2026-11-06 · Code: `src/worker/rag/answer.ts` (pipeline), `src/worker/llm.ts` (streaming + fallback), `src/worker/routes/chat.ts` (`POST /api/chat`, SSE), `scripts/eval-answers.ts` · Data: production D1 + Vectorize (20 papers) · LLM: Groq

## What was built

`answer()` runs these steps as plain functions (D-010):

1. **Clean** the question: invisible characters are stripped, and the route caps it at 1,000 characters.
2. **Guard** (T-4.1), in three layers:
   - A regex speed bump for override attempts ("ignore … instructions", "system prompt", "you are now", "jailbreak").
   - A keyword list for weapon chemistry.
   - A one-word classification by `gpt-oss-20b`: ON_TOPIC, OFF_TOPIC or HAZARDOUS. If the classifier call fails, the guard lets the question through; the answer prompt still refuses hazards.
3. **Rewrite** (T-4.2): runs only when the chat has history, which comes from D1 (last 10 `ok` turns). The client cannot send history: the strict schema rejects it.
4. **Retrieve**: the P3 pipeline, giving up to 6 passages within a 3,000-token budget.
5. **Prompt** (T-4.3):
   - The system prompt is fixed on the server and carries a per-request canary (`SIQ-xxxxxxxx`).
   - Sources go in a `<sources>` fence, each as `[n] title (year) · section · p.x–y`.
   - Tag-like strings in paper text, titles and the question are neutralised (`</sources>` → `‹/sources›`). Comparison signs such as `p < 0.05` are left alone.
6. **Generate** (T-4.4):
   - Groq, streamed, temperature 0.2, `reasoning_effort: low` with reasoning hidden, max 1,000 tokens (about 800 for the answer plus low-effort reasoning).
   - The fallback chain moves on after a 429, a 5xx, a connection error or a **stalled stream (30 s deadline per model)**. It only switches before the first token.
7. **Validate** (T-4.5):
   - `【n】` is converted to `[n]` (gpt-oss writes `【1】`).
   - Every cited number must be a source that was sent. An answer with no citations is only allowed if it is the exact "I couldn't find this in the papers." reply. An answer containing the canary is rejected.
   - On failure the answer is regenerated once; the client gets `replace` and clears the draft. If it fails again, the user gets the couldn't-find reply with status `unverified`.
   - The stream holds back the last characters until they are checked, so a leaked canary is never sent.
8. **Save** (T-4.7):
   - Both messages are saved, with `citations_json = [{ n, chunkIds }]`, the status and the model.
   - The `done` event carries the cited sources as **stored** passage text with title, DOI, pages and an upload flag (SECURITY §7.2).
   - **KV cache:** only for questions with no history from owners with no uploads (key `ans:v1:public:<sha256 of normalised question>`, 24 h). Declined answers are not cached.

SSE events: `status` (searching / writing), `token`, `replace`, `done`, `error`. Error messages are generic, and provider errors are never passed through.

## T-4.8 Answer evaluation (`npm run eval -- --answers`)

Live run, local pipeline on production data, Groq for both the answers and the judge.

- **Judge:** an LLM gets the question, the human reference answer, the cited source text and the answer. It returns `faithful` (every claim supported by the cited sources) and `correct` (yes / partial / no).
- **Hand check:** I read every answer the judge flagged and checked the claims against the passages.

**Run 1** (chain `gpt-oss-120b → qwen3.8-27b → gpt-oss-20b`):

| Metric | Result |
|---|---|
| Answered with valid citations | 35/35 |
| Faithful (judge) | 30/35 |
| Faithful (after hand check) | **31/35 (89%)**: the judge was wrong on q03; both figures are in source [1] |
| Correct, key fact present | 32/35, plus 3 partial (q16, q19, q33 each miss one point) |
| Correct declines on unanswerable questions | **5/5 (100%)**: 4 "couldn't find", 1 off-topic decline (target ≥ 90%) |
| Live injection and guard cases | **6/6** (SEC §13 #7, #8, #9, #15 off-topic, #15 jailbreak, #22 phosgene, the last caught by the model guard, not the keyword list) |
| First drafts rejected for missing citations | 3, all fixed by the single retry |
| Median time per answer (guard → retrieval → full answer) | 2.8 s |

**Finding:** all 4 unfaithful answers (q04, q11, q16, q28) came from `gpt-oss-20b`, the last model in the chain: 4 unfaithful out of the 12 answers it wrote, against 0 of 23 from the other two. It wrote 12 of 35 answers only because the bigger models hit Groq's 8,000 tokens/min limit during the run. Its errors were extra claims that weren't in the sources ("lower aspect ratios", "Staphylococcus", "increased spoilage") and one reversed claim (q16).

**Change (D-013):** `LLM_MODELS` is now `openai/gpt-oss-120b,qwen/qwen3.8-27b`. `gpt-oss-20b` remains the small model for guard and rewrite.

**Run 2**, the 12 questions `gpt-oss-20b` had answered, now answered by the two-model chain: **12/12 faithful, 12/12 correct**. Combined with run 1's 23 answers from the other two models (all faithful after the hand check), **35/35 answers are faithful.**

**Bug found by run 2 and fixed:** q16 took 477 s. The SDK timeout only covered the time to the first response, so a stream that stalled afterwards could hang indefinitely, and Cloudflare REST calls had no timeout at all. Now:
- each model gets a 30 s deadline that also covers the stream (a stall counts as retryable);
- every REST call has a 20 s timeout.

There is a regression test for the stall.

## Capacity (decision needed before launch)

- One answer uses about 4,000–5,000 tokens: about 3,500 of prompt (3,000 of sources) plus the answer, and the guard adds about 600.
- Groq allows **8,000 tokens per minute per model**, so the two answer models together handle roughly **3–4 answers per minute**. Beyond that, users get the "busy" message.
- The KV cache helps only with repeated questions.

Options for P8:
- a smaller source budget (for example 2,000 tokens);
- a paid Groq tier;
- or keep `gpt-oss-20b` as a last resort that labels its answers.
