## T-6.1 / T-6.3 API

| Endpoint | Scope and rules |
|---|---|
| `GET /api/papers` | `owner_id IN ('public', me)`, status `ready`, and the upload has not expired. Authors are parsed from JSON; only `https://` source links are returned. Returns the whole visible library (≈ 25 rows). The code comment `shortcut:` says to paginate past a few hundred papers. |
| `GET /api/papers/:id` | Same scope. Returns the paper, its sections (name and pages) and the abstract (or the first section) as a summary. Another owner's paper, an expired upload or a malformed ID all return **404**. |
| `GET /api/chats` | The caller's chats, newest activity first (100 max). |
| `GET /api/chats/:id` | The messages in order. An assistant message's sources are **rebuilt from the stored chunk IDs through `fetchChunks`**, the same owner re-check as search. The panel therefore shows stored text, and a deleted or foreign chunk drops out. A planted citation to user B's chunk is never revealed (tested). |
| `PATCH /api/chats/:id` | Strict `{ title }`, 1–80 characters, cleaned; extra fields return 400. |
| `DELETE /api/chats/:id` | Deletes the messages, then the chat, in one batch, both owner-scoped. |

Tests (`test/library.test.ts`, 7, SEC §13 #1): A sees only public papers and A's live uploads. B's chat returns 404 for open, rename and delete. The tampered citation is dropped. Overlapping neighbour chunks are joined. Rename is validated. Delete removes the messages and leaves B's chat alone.

## T-6.2 / T-6.4 UI

- **Library** (`src/web/pages/Library.tsx`):
  - Search matches every word across title, authors, journal, topic and year.
  - Topic filters are toggle buttons with `aria-pressed`; "Your uploads" appears only when you have uploads.
  - Cards show the Curated or "Your upload · unverified" badge. There are loading, error-with-retry and no-match states.
  - **Detail:** abstract, sections with pages, a DOI link we build ourselves, the "Open the PDF" source link (`rel="noopener noreferrer nofollow"`), and **Ask about this paper**, which starts a new chat with the question.
- **Routing:** `#/library` and `#/library/<id>` via `pushState`/`popstate`, so the browser back button works. Only known routes are parsed (tested).
- **History sidebar:** loaded from the API and grouped into Today / Yesterday / Previous 7 days / Older.
  - Opening a past chat rebuilds its turns: couldn't-find answers, busy errors and a question saved with no answer (shown as failed, with retry).
  - Citations and thumbs come back as they were saved. Follow-ups continue the same server chat.
  - The open chat has **Rename** (inline input: Enter saves, Esc cancels) and **Delete** (asks to confirm first).
- **Contrast:** "Ask about this paper" uses the soft accent with an accent outline; text on the accent would be 4.2:1 (the P5 rule).

## Recommendation 2: front matter out of the index

**Parser** (`src/shared/pdf/structure.ts`):
- Front matter keeps prose sentences.
- It drops sentences that contain an email, ©, licence or open-access wording, "Received/Accepted/Published + date", "Edited by", "Reviewed by", "Correspondence", "Citation:" or ORCID.
- It drops affiliation lists (lines starting with "1 Department of…" and similar), and paragraphs with under 100 characters of prose left.
- Contact footnotes are stripped from **every** section.

Getting there took three tries:
1. Dropping whole paragraphs also lost real prose: a sentence citing a URL, and one introduction.
2. A lowercase-word "prose test" lost chemistry sentences.
3. The sentence-level marker filter kept every abstract opening I checked (DES lignin, the chitosan hydrogel, the photoredox standfirst).

There are 3 new unit tests.

## Findings

1. **Groq's daily token limit is the real capacity ceiling.** The free tier gives `gpt-oss-120b` **200,000 tokens per day**. At about 4,500 tokens per answer, that is roughly **40–45 answers per day** per answer model, before the guard and rewrite calls. Today's evals used it up (197,728 of 200,000), so the live demo falls back to the second model until the limit resets. The per-minute limit (8,000) noted in P4 is the smaller problem. **For P8:**
   - keep evals off the demo's quota (a separate key or project);
   - read the budget from configuration (the owner's P8 rule: nothing hard-coded);
   - show the "busy" state early;
   - consider a paid tier for the launch.
2. **Eval bug, fixed:** "busy" results were counted as failed declines and, worse, as **passed** injection cases (a busy reply trivially "doesn't say HACKED"). `eval-answers.ts` now marks them *not measured* and leaves them out of every share, and the summary reports an `unavailable` count.
3. **A citation number can point at the wrong source (q06).** The validator checks that every `[n]` exists; it does not check that `[n]` supports the claim. A groundedness check (RAG §5.11, small judge or NLI) is the fix. It goes on the P8 hardening list.
